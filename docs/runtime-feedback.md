# Runtime capture, identity and telemetry

The native CLI supports debugger captures and fixed Frida recipes. Frida 17.17.0
is statically linked into a private native helper embedded in `indago`, alongside
the existing DbgEng/DynamoRIO payloads. No Python, installed Frida CLI or server
is needed. Ghidra/JDK are now privately embedded too; see the
[Ghidra workbench](ghidra-workbench.md).

## Capture and feedback

```text
indago runtime capture --project demo --session RUN --address 0xADDRESS --size 4096
indago runtime reanalyze --project demo --session RUN --observation OBS --backend both
indago runtime identities --project demo --session RUN --kind epoch
indago runtime identities --project demo --session RUN --kind lifetime
indago runtime lineage --project demo --session RUN --artifact SHA256
```

Capture requires a stopped debugger session. Omit address to capture the PC;
static-address, RVA and function selectors are also accepted. Code reads are
bounded to 64 KiB. GP registers and the original PC instruction window remain
separate from the requested code region so captured symbolic execution is still
seeded at the correct PC. Empty/unreadable code does not invent an epoch.

Each nonempty read gets a distinct code epoch: run, process instance, address
space, observed module lifetime when known, range, exact byte hash, method and
coverage. Equal bytes from separate reads do **not** assert continuity. Runtime
locations retain file anchors only as file-identity claims, not proof of live
byte equality. Exec changes address-space identity. Snapshot-only debugger
lifetimes explicitly allow missed unload/reload activity. Frida reports module
and thread observer instances, bounded by collection coverage. A lifetime's
last observation can be collection closure, not an observed native exit.

Reanalysis persists raw bytes in the content-addressed store and creates one
explicitly synthetic ELF analysis container with a single RX segment at the
observed address. Only that contiguous captured range is mapped. Headers and
entry selection are labeled synthesized. No missing pages, imports or runnable
image reconstruction are claimed. It runs bounded XAIR inventory/CFG/semantics
and/or Ghidra import/decompile/tokens/CFG. Jobs/evidence retain native results;
their evidence records link to the source observation, epoch, raw artifact and
exact runtime/analysis/file-offset mapping. Ghidra and XAIR remain separate views.
An arbitrary capture boundary need not be a true function entry.

`reanalyze` is an explicit synchronous action, not automatic execution of captured
bytes. Its per-analysis timeout defaults to 60 seconds. Partial reads and failed
backends remain partial feedback; successful backend evidence is not discarded.
Lineage is persisted before analysis, so it survives interrupted analysis. The
existing static job cancellation/recovery endpoints still apply to those jobs.
Core schema 4 adds indexed artifact derivations; runtime schema 2 adds indexed
code epochs and observed lifetimes. Older observations remain readable but do
not retroactively acquire missing byte identities.

## Frida recipes

```text
indago runtime recipes
indago runtime instrument --project demo --file trusted.exe --backend frida --recipe code --max-events 256 --timeout-ms 5000
indago runtime status --project demo --session RUN
indago runtime observations --project demo --session RUN --kind code_capture
indago runtime cancel --project demo --session RUN
```

- `modules`: module/thread lifetime callbacks.
- `io`: selected file/read/write/close/connect/send/recv exports; correlated API
  entry/return, caller address, raw arguments/returns, error state and bounded
  path/buffer excerpts. Windows async I/O is not claimed as completed data.
- `code`: VirtualAlloc/VirtualProtect or mmap/mprotect hooks; after successful
  executable allocation/protection, capture at most 4096 bytes. These observations
  can feed the same `reanalyze` operation. A concurrent read is not a coherent
  process snapshot or proof that generated bytes executed.

All recipes preserve original Frida JSON envelopes and producer sequence/clock,
plus collector order/time. Limits: 10,000 events, 60 seconds, 4 MiB raw events,
64-byte I/O excerpts. Unavailable hooks, dropped/capped output, read failures and
timeout are explicit. Timeout/cancel terminates the explicitly launched process;
attach via `--pid` is now supported and cancellation detaches without killing the
existing process. Instrumentation is separate from debugger controls.

This is selected user-space telemetry, **not** universal syscall/network capture,
child-process following, full write tracking or lossless replay. Direct syscalls,
pre-install activity and some loader events
may be absent. Frida hooks alter code and timing; observer cost is not calibrated.
The host still executes targets without a sandbox: use trusted fixtures only.

Build helpers: `tools/build-frida.ps1` / `.sh`, then rebuild `indago`. Basic smoke
checks live in `tests/runtime_feedback_smoke.ps1` and `tests/frida_smoke.ps1`;
they are not the deferred production qualification gate.
